# Issue-заготовки для доработки продвинутого бота

Документ создан по [issue #29](https://github.com/mlaa4ml/durakProekt/issues/29).
Источник — [`SMART_BOT_PLAN.md`](SMART_BOT_PLAN.md) (согласован в issue #26),
блокер issue #27 («боты видят руки всех игроков») закрыт.

Здесь лежат **готовые тексты issue** для этапов 1–7 из раздела 9 плана: заголовок,
контекст, объём работ, список файлов, критерии приёмки (DoD) и проверки.
Каждый этап = одна issue = один PR. **Следующий этап не начинается, пока предыдущий не принят.**

## Решения заказчика (issue #29) — обязательны для всех этапов

| # | Вопрос из раздела 11 плана | Ответ заказчика |
|---|---|---|
| 1 | Названия уровней в UI | «простой» / «умный (считает карты)» — **утверждено** |
| 2 | `botExplain` по умолчанию | **выключен** — утверждено |
| 3 | Целевая метрика G2 | доля «дурака» у `smart` ≤ 45 % на 1000 партий — **условие мержа** |
| 4 | Порядок работ | локальный клиент (этапы 4–5) → сеть (этап 6) — утверждено |
| 5 | Третий «лёгкий» уровень | **не делаем**, уровней ровно два |

> Отдельно: финальный прогон метрики G2 и решение о мерже заказчик делает **сам, руками**.
> Исполнитель метрику только измеряет и прикладывает цифры к PR, но не «принимает» её за заказчика.

## Общие правила для всех этапов (копировать в каждую issue)

* Работа ведётся в отдельной ветке, PR затрагивает **только файлы своего этапа**.
* Поведение `simpleBotDecide` из `src/bots/simpleBot.js` **не меняется** ни на одном этапе:
  на нём висят `src/cli/simulate.js`, `src/cli/playVerbose.js`, `scripts/smoke.js`,
  `server/rooms.js` и локальный клиент.
* Бот получает **только** `game.getState(botId)` — маскированное состояние без чужих рук.
* CI (`.github/workflows/ci.yml`) должен быть зелёным: `playVerbose`, `simulate` с
  «Ошибок движка: 0» на всех конфигурациях, HTTP-эндпоинты сервера, `npm run smoke`.
* `visual/index.html` и `docs/index.html` обязаны остаться **байт-в-байт одинаковыми**.

## Issue 1 — Этап 1. Бенчмарк ботов и реестр уровней

**Labels:** `bot`, `priority:p1`
**Зависит от:** —

### Контекст
Раздел 9, этап 1 плана. В #24 умный бот оказался слабее простого, и выяснилось это поздно.
Поэтому **инструмент измерения пишется до самого бота**.

### Что сделать
1. `src/bots/index.js` — реестр уровней:
   ```js
   export const BOT_LEVELS = [
     { id: 'simple', label: 'Простой',               description: 'Базовые эвристики, ничего не запоминает' },
     { id: 'smart',  label: 'Умный (считает карты)', description: 'Помнит вышедшие карты, анализирует стол, объясняет ходы' },
   ];
   export const DEFAULT_BOT_LEVEL = 'simple';
   export function normalizeBotLevel(x)  // неизвестное -> DEFAULT_BOT_LEVEL
   export function botLevelLabel(id)
   export function createBotBrain(level, options = {})  // { level, reset(), observe(), decide() }
   ```
   На этом этапе реально реализован **только уровень `simple`** — тонкая обёртка,
   `decide()` возвращает `{ action: simpleBotDecide(state, playerId, legalActions) }`.
   Уровень `smart` пока падает обратно на `simple`; это поведение зафиксировать в PR.
2. `src/cli/botMatch.js` — очный матч уровней:
   `node src/cli/botMatch.js <партий> <levelA> <levelB> <deckSize> <numPlayers> [--verbose]`.
   Печатает: число партий, конфигурацию, ошибки движка, зависания, ничьи,
   долю «дурака» по уровням и по местам. Матч гоняется **в обе стороны**
   (levelA на 1-м и на 2-м месте), чтобы исключить перекос по местам.
   `--verbose` печатает лог одной партии вместе с `reason`/`analysis`.
3. `package.json`: скрипты `bot-match` и `sync-client`
   (`sync-client` копирует `visual/index.html` → `docs/index.html`).
4. `scripts/sync-client.sh` + шаг в CI: `cmp -s visual/index.html docs/index.html`,
   иначе сборка падает.

### Файлы
`src/bots/index.js`, `src/cli/botMatch.js`, `scripts/sync-client.sh`,
`package.json`, `.github/workflows/ci.yml`

### DoD
* `node src/cli/botMatch.js 1000 simple simple 24 2` даёт ~50/50 (инструмент не врёт),
  0 ошибок движка, 0 зависаний;
* CI зелёный, шаг проверки идентичности клиентов работает (проверить «на отрицательном»:
  умышленно расходящиеся файлы валят сборку);
* поведение простого бота не изменилось: `simulate` даёт те же порядки цифр,
  `src/bots/simpleBot.js` не тронут.

## Issue 2 — Этап 2. Память бота: `CardTracker`

**Labels:** `bot`, `priority:p1`
**Зависит от:** Issue 1

### Контекст
Раздел 4 плана. Трекер на этом этапе **ни на что не влияет** — только наблюдает,
чтобы его можно было проверить изолированно.

### Что сделать
`src/bots/memory.js` — класс `CardTracker(deckSize, trumpSuit, trumpCard, meId, playerIds)`
с полями `all / discard / onTable / takenBy / seenPlayed / voidSuits / trumpCard`
и методом `observe(state)`, который сравнивает свежий `state` с предыдущим снимком
(таблица событий — раздел 4.3 плана).

Публичный API (раздел 4.4):
`unknownCards()`, `opponentPossibleCards(oppId)`, `opponentKnownCards(oppId)`,
`isOpponentHandCertain(oppId)`, `probabilityOpponentHas(card)`,
`highestRemaining(suit)`, `trumpsLeftOutside(myHand)`.

**Точные** факты (`discard`, `onTable`, `takenBy`) хранятся отдельно от
**предположений** (`voidSuits`, «спасовал → нет ранга»).

### Файлы
`src/bots/memory.js`, `test/memory.test.js`

### DoD
* юнит-тесты (`node:test`) зелёные на сценариях: карты ушли в бито; защитник взял стол;
  добор из прикупа; последняя карта прикупа = `trumpCard` (становится известной);
  эндшпиль при пустом прикупе;
* фаззинг-прогон дуэли: при `talonCount === 0` трекер восстанавливает руку соперника
  **точно в 100 %** прогонов;
* прогоны на 3/4/6 игроков не приводят к ложным «точным» фактам
  (при неопределённости трекер честно возвращает «не знаю»);
* CI зелёный, движок и простой бот не тронуты.

## Issue 3 — Этап 3. Умный бот: анализ и политика

**Labels:** `bot`, `priority:p1`
**Зависит от:** Issue 2

### Контекст
Разделы 5 и 6 плана. Это та часть, где провалились #24/#25, поэтому каждая эвристика
включается **только по цифрам** A/B-прогона на `botMatch`.

### Что сделать
1. `src/bots/analysis.js` — чистые функции без состояния:
   `beats`, `cardPower`, `handStrength`, `planDefense`, `unbeatableCards`, `suitControl`.
2. `src/bots/smartBot.js` — политика решений (атака/подкидывание, защита/перевод/взятие, пас)
   по разделу 5.3, с профилем флагов:
   ```js
   const SMART_PROFILE = {
     holdTrumpsWhileTalon: true, finishOffWeakOpponent: true,
     takeWhenTableUnbeatable: true, exactEndgame: true, dumpPairs: true,
   };
   ```
3. `decide()` возвращает `{ action, reason, analysis }`; тексты на русском, без терминов кода
   и **без раскрытия того, чего бот не знает**.
4. Уровень `smart` регистрируется в `src/bots/index.js` как настоящий.

### Файлы
`src/bots/analysis.js`, `src/bots/smartBot.js`, `src/bots/index.js`,
`test/analysis.test.js`, `test/botLegality.test.js`

### DoD
* фаззинг легальности: 5000 партий, **ни одного** нелегального действия;
* инвариант «бот не подглядывает»: в `decide()` приходит состояние без чужих `hand`
  (проверяется тестом);
* метрика G2: `node src/cli/botMatch.js 1000 smart simple 24 2` → доля «дурака» у `smart` **≤ 45 %**,
  то же для `36 2`; на `36 4` и `52 3` — **не хуже** простого;
* каждый флаг `SMART_PROFILE` подтверждён A/B-прогоном (флаг вкл/выкл): флаг, который
  не улучшает метрику, выключается, и это фиксируется в PR таблицей;
* таблица метрик приложена к PR.

> Приёмка метрики — за заказчиком: он гоняет `botMatch` руками и решает, мержить ли.
