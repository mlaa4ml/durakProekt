# Предложение дизайна для #80

Ветка: `openai-gpt-6-astra-issue-80`. Это первый вариант для проверки,
не утверждённый макет. Правила игры и выбор допустимых ходов не меняются.

## Что предлагается

- **Стабильный стол.** На компьютере лоток заранее резервирует место под две
  строки пар. На телефоне основной вариант — одна горизонтально прокручиваемая
  лента высотой 143 px. Добавление защиты не расширяет пару: её ширина уже
  учитывает сдвиг защитной карты.
- **Альтернатива без длинной ленты.** Настройка «Стол на телефоне → перенос
  вниз» оставляет лоток высотой 270 px. Излишек прокручивается внутри, а не
  толкает руку вниз. Это больше места для стола ценой дополнительного
  вертикального пространства.
- **Крупные карты руки, видна верхняя часть.** На телефоне карта при 100%
  имеет размер 112 × 158 px, нижняя часть обрезана лотком. Угол с рангом и
  мастью остаётся виден. Между началами соседних карт минимум 44 px;
  большая рука прокручивается свайпом, а не сжимается до тонких полосок.
  Ползунок размера 70–160% сохранён. На компьютере остаётся веер.
- **Информация по приоритету.** Козырь, роли, колода и бито собраны в HUD
  из двух колонок. На телефоне убраны дублирующие колода и бито по бокам:
  освободившееся место отдано картам. Соперники расположены компактным рядом.
- **Выбор действия не толкает стол.** Панель заранее резервирует 112 px
  под кнопки «Отбиться / Перевести / Отмена» и «Взять карты». При избытке
  кнопок прокрутка остаётся внутри панели.
- Светлая и тёмная палитры сохранены: сначала проверяем геометрию и
  читаемость, не меняя одновременно привычные цвета.

## Схема двух вариантов (не скриншот)

```text
Телефон, «скролл вбок»           Телефон, «перенос вниз»
┌────────────┬────────────┐      ┌────────────┬────────────┐
│ козырь     │ атакует    │      │ козырь     │ атакует    │
│ защищается │ колода     │      │ защищается │ колода     │
│ бито       │ ваш ход    │      │ бито       │ ваш ход    │
├────────────┴────────────┤      ├────────────┴────────────┤
│ соперники: имя / карты  │      │ соперники: имя / карты  │
├─────────────────────────┤      ├─────────────────────────┤
│ пары атака+защита  →    │      │ пары атака+защита       │
│ фиксированный лоток    │      │ вторая строка          │
├─────────────────────────┤      │ фиксированный лоток ↕  │
│ крупные углы карт   →  │      ├─────────────────────────┤
│ действия               │      │ крупные углы карт   →  │
│ подсказка хода          │      │ действия / подсказка   │
└─────────────────────────┘      └─────────────────────────┘
```

## Проверка перед публикацией

1. Node.js 20+, `npm ci`, `npm run build-client`.
   Сгенерированные `visual/index.html` и `docs/index.html` должны войти
   в ветку; вручную их не редактировать.
2. `node --test test/handLayout.test.js test/clientBuild.test.js`,
   затем `npm test` и `npm run build-client -- --check`.
3. `npm run server`, открыть `/visual/` (порт уточняется в выводе сервера).
4. Проверить ширины 320, 390, 680, 1024 px, светлую и тёмную темы:
   - «Играю против ботов», скрыть чужие карты; затем просмотр с открытыми;
   - 2 и 6 игроков, колода 36/52;
   - пустой стол → атака → защита → несколько пар → взятие → отбой;
   - оба варианта раскладки стола;
   - выбор «Отбиться / Перевести», отмена и выполнение;
   - рука 1/6/много карт, масштаб 70/100/160%, последняя карта доступна;
   - поворот телефона / смена ширины: нет горизонтальной прокрутки всей
     страницы, углы читаемы, кнопки доступны;
   - сетевой режим использует ту же геометрию, не закрывает подсказки.
5. Сравнить высоту `.mid-row` и положение `.my-hand-wrap` до/после
   добавления защиты и второй строки. При неизменном размере окна
   высота лотка не должна меняться. Изменение масштаба рукой пользователя
   и переключение варианта раскладки могут менять высоту намеренно.

`test/handLayout.test.js` проверяет только алгоритм координат, не CSS и не
реальные касания. Браузерную проверку нельзя считать выполненной по этому тесту.

## Текущее ограничение проверки

Создание Codespace вернуло HTTP 402: у владельца исчерпана бесплатная
квота либо лимит бюджета. Поэтому сборка, тесты и браузерный просмотр в
облачной среде пока не выполнены. Схемы выше — предложения, а не результаты
визуальной проверки.
