# Диагностика решений SmartBot (#69)

`new SmartBot({ trace: true, explain: true })` (или `createBotBrain`) возвращает
`{ action, decisionTrace, reason, analysis }`. Оба переключателя независимы:
`trace` включает структурированные метаданные, `explain` — русский текст.
Выключение любого из них не переключает стратегию.

## Схема версии 1

- `version`: версия схемы.
- `actionId`: до применения действия — `null`. CLI и локальный клиент связывают
  решение с очередным действием; recorder назначает авторитетный ID записи
  архива (включая ходы человека).
- `selectedRule`: идентификатор фактически выбранной ветки политики.
  `exact-solver` означает принятый полный поиск;
  `emergency-first-legal` — аварийный выбор первого легального действия.
- `emergencyFallback`: была ли задействована аварийная страховка.
- `handKnowledge`: `exact` / `unknown`, точность знания руки текущего соперника,
  а не содержимое его руки.
- `profile`: имя, версия калибровки (`1`) и реально включённые флаги профиля.
- `solver`: `enabled`, `applicable`, `status`, `solved`, `timedOut`, `value`,
  `nodes`, `ms`. Значение относится к результату поиска, не к оценке эвристики.
  У незапущенного поиска `value: null`, узлы и время равны нулю.

Статусы поиска:

| status | Значение |
| --- | --- |
| `disabled` | флаг точного решателя выключен |
| `unknown-hand` | точная рука не восстановлена |
| `not-applicable` | прочие ограничения решателя (фаза, прикуп, число игроков, правила) |
| `budget` | поиск исчерпал бюджет; полного решения нет |
| `legal-mismatch` | результат не соответствует легальным действиям движка |
| `unusable` | нет пригодного полного результата |
| `proven-loss` | полный поиск доказал проигрыш; политика перешла к эвристике |
| `used` | полный поиск принят |
| `exception` | исключение при выборе; включается аварийный fallback |
| `not-attempted` | поиск ещё не запускался |

Приоритет статусов: отключённый флаг, неизвестная рука/неприменимость,
затем результат поиска. `applicable` вычисляется независимо от флага.
Русский `reason` использует тот же результат: при откате сообщает его причину
и затем реально выбранную эвристику. Только принятый полный поиск обещает
просчитанный исход. Доказанный проигрыш не превращается в обещание выигрыша
при выборе эвристики.

## Где смотреть

- CLI: `playOneGame(..., true)` возвращает `trace[].decisionTrace`;
  `recordDiagnostic: true` сохраняет trace и без пошагового текстового вывода
  в `diagnostic.actions[].decision.decisionTrace`.
- Локальный клиент: включить объяснения умного бота; строка «диагностика»
  содержит JSON рядом с объяснением действия.
- Диагностический replay воспроизводит записанные действия, не запускает
  заново поиск с неповторяемым временным бюджетом.

Сам trace не содержит карт, рук, поисковых позиций или текстов исключений.
Он не добавляется в сетевые state-сообщения. Полный replay-архив содержит
приватные данные и по-прежнему предназначен только для защищённого хранения
(см. `DIAGNOSTIC_REPLAY.md`).

## Позиция #64

Подключение бота только к изображённой поздней позиции не восстанавливает
пропущенную публичную историю: trace показывает `unknown-hand`, а не `budget`.
При полной истории наблюдений и точном знании руки исчерпание бюджета
отмечается отдельно как `budget` с `timedOut: true`. В обоих случаях
`selectedRule` показывает фактическую эвристику, а не намерение решателя.
Исторические настройки и память бота #64 неизвестны — тест не объявляет
реконструкцию replay всей исходной партии.

Проверки: `node --test test/decisionTrace.test.js test/issue64Position.test.js`.
Они включают полный реальный поиск, бюджет в обеих фазах, реальные
`getState(id)` / `getLegalActions(id)` и публичную историю, проверки откатов
на контролируемых результатах решателя, независимость действий от диагностики
и связь ID с replay.
