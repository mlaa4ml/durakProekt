# Диагностическая история партии (issue #67)

## Запись и replay

Серверные комнаты автоматически записывают действия людей и простых ботов.
После завершения партии `server/matchLog.js` сохраняет прежний текстовый лог
и поле `diagnostic` в `logs/<дата>-<комната>.json`. Каталог задаётся
`DURAK_LOG_DIR`, запись на диск отключается `DURAK_SAVE_LOGS=0`.
Отключение записи на диск не отключает сбор истории в памяти комнаты.

Воспроизведение (Node.js 20+, из корня **той же версии исходников**):

```sh
node src/cli/replay.js logs/<дата>-<комната>.json
# или отдельный diagnostic JSON:
node src/cli/replay.js /private/path/game.json
```

CLI печатает только статус, число действий и результат, без рук.
При неверном JSON, формате, версии или рассогласовании истории завершает
работу с кодом 1 и сообщением `Replay failed: ...`.

В общем ядре матчей ботов запись включается явно: `recordDiagnostic: true`.
Пример создания защищённого файла, включая незавершённую диагностическую партию:

```sh
mkdir -p /tmp/durak-private
chmod 700 /tmp/durak-private
node --input-type=module <<'JS'
import { writeFileSync } from 'node:fs';
import { playOneGame } from './src/cli/matchCore.js';
const result = playOneGame(['simple', 'simple'], 24, 2, true, {
  recordDiagnostic: true,
});
writeFileSync('/tmp/durak-private/game.json',
  JSON.stringify(result.diagnostic, null, 2),
  { mode: 0o600, flag: 'wx' });
JS
node src/cli/replay.js /tmp/durak-private/game.json
```

Для SmartBot можно передать уровни `smart` и `seatOptions` (profile, solver).
В артефакте сохраняются фактически разрешённый профиль и настройки solver.
Обычные бенчмарки без `recordDiagnostic` не накапливают историю приватных рук.
Локальный браузерный клиент пока не записывает этот Node-only артефакт.

## Контракт JSON v1

Внешний серверный лог остаётся версии 1; описанная ниже версия относится
именно к его полю `diagnostic` либо к самостоятельному артефакту:

- `format: "durak-diagnostic"`, `version: 1`, `engineVersion: 1`;
- `buildVersion`: SHA-256 фактических исходников движка, правил, колоды
  и всех модулей `src/bots/*.js`. Это fingerprint кода, не Git SHA.
  Изменение исходников требует replay на исходной ревизии. Профиль
  идентифицируется этим fingerprint вместе с сохранёнными значениями;
- `rules`: полные разрешённые правила;
- `players`: упорядоченный состав `{id, name}`;
- `participants`: начальный вид участника, уровень, профиль, при наличии
  настройки solver. Замена человека ботом отражается в `decision.actor`;
- `initialDeck`: **приватная** полная упорядоченная начальная колода:
  последовательные руки по местам, затем прикуп. Последняя карта — козырь.
  Этого достаточно вместо seed; RNG при replay не используется для раздачи;
- `initialSnapshots`: массив `{playerId, state}` из реального `getState(id)`;
- `actions`: последовательные записи с `id`, начиная с 1 без пропусков,
  `playerId`, `snapshot` перед ходом, `legalActions`, выбранным `action`,
  `decision`. Отклонённые действия не расходуют ID;
- `decision`: `null` либо `{actor, reason, decisionTrace}`. Пустой
  `decisionTrace: null` — зарезервированное место для этапа 3,
  а не выдуманная причина/доказательство работы решателя;
- `outcome`: фаза, дурак, причина ничьей, порядок выхода, маскированные
  снимки по местам в конце сохранённой последовательности.

`GameRecorder` устанавливается сразу после создания `DurakGame`, до первого
действия; после этого действия должны идти через `applyAction`, а не через
внутренние методы движка или прямые изменения позиции. Клоны для поиска
не инструментируются. Снимки/экспорт — независимые JSON-копии.
Это диагностический архив выбранных действий, а не полная трасса вызовов
`brain.observe`/`brain.reset` и не доставка наблюдений всем ботам (этап 2).

Replay создаёт реальный `DurakGame` с сохранённой колодой, проверяет правила,
каждый `getState(id)`, `getLegalActions(id)`, легальность выбранного действия,
вызывает `applyAction` и сверяет итог. Проверяется также поле `against`
защитного действия. Повреждённая или обрезанная история с несовпадающим итогом
отклоняется. Это проверка согласованности, **не криптографическая подпись**
против намеренной подмены всего артефакта.

## Граница приватности

Каждый отдельный snapshot содержит `hand` только владельца; чужие руки
не передаются боту. Но **объединённый архив всё равно содержит все руки**,
поэтому его нельзя отдавать ботам, в live UI, WebSocket payload или
публичный текстовый лог. `GameRecorder` не добавляет данные в `getState`
или `game.log`. Сервер передаёт архив только сохранению после окончания.

Экспорт незавершённой партии запрещён по умолчанию. Для доверенного
диагностического кода предусмотрено явное
`exportArtifact({protectedDiagnostic: true})`; это обязательство вызывающего
кода обеспечить защищённое хранилище, не аутентификация пользователя.

Сервер создаёт новый каталог с правами 0700, файлы — 0600, без перезаписи
существующих файлов. Права уже существующего каталога не изменяются:
оператор должен проверить их и не размещать `DURAK_LOG_DIR` внутри
публично обслуживаемой директории. Ограничьте доступ к резервным копиям;
не публикуйте живую партию в issue. Послеигровая публикация — только
осознанно, с учётом имён участников и раскрываемой раздачи.
Архив хранится в памяти до завершения; авария процесса до сохранения
может потерять историю. Потоковая запись/ротация не входят в этот этап.

## Ограничения вывода по #64

Исходная партия #64 целиком неизвестна: начальная раздача, все настройки,
версия бота и полная история наблюдений не восстановлены.
`test/issue64Position.test.js` не заменён и не продублирован: его 18 проверок
по-прежнему проверяют реконструированный раунд (A♠ в начале и J♣ перед
последней защитой легальны и вынуждают взятие; после четвёртой защиты — пас).
Реконструкция не доказывает, что бот знал руку соперника, и не доказывает
итоговый выигрыш альтернативы. Новый replay воспроизводит **сохранённые
действия**, не повторяет решения бота с временными бюджетами и не является
доказательством стратегического улучшения.

ошибки формата/версии и рассогласование снимков; изоляцию рук;
серверный транспорт, права файла и запуск CLI.
