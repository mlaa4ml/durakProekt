# Локальные публичные наблюдения (#68)

CLI `playOneGame`, просмотр bot-vs-bot и интерактивная игра используют
`applyObservedAction(game, brains, actor, action)`. Сервер не подключён:
его автодействия по-прежнему выполняет простой бот.

## Контракт

После успешного действия движок публикует **один** `publicTransition`:

- `actionNumber`: последовательный номер действия, начиная с 1 в новой партии;
- `actor`, `action`: автор и нормализованное легальное действие; только тип и
  сыгранные карты (`card` либо `cards`), без руки, лога и пользовательских полей;
- `closures`: закрытия столов в порядке выполнения внутри этого действия.
  Каждое содержит `destination` (`discard` / `hand`), `defender` и полный список
  публичных карт закрываемого стола;
- `trumpDraws`: получатель и карта последнего добора при опустошении колоды.
  Это ранее открытый нижний козырь. Обычные закрытые карты добора не публикуются.

Порядок обработки: сыгранные карты → закрытие стола → открытый козырь →
маскированное конечное состояние. Закрытия фиксируются **перед очисткой стола**,
поэтому последняя карта защиты/подкидывания не исчезает для наблюдателей даже
при синхронном закрытии, доборе и запуске следующего раунда в одном `applyAction`.
Пустое техническое закрытие не создаёт запись.

Сохраняется только последний пакет, не вся история партии. Тихие позиции
решателя не создают пакеты. Копия обычной партии сохраняет номер и независимую
копию последнего пакета.

Адаптер доставляет пакет сразу после действия всем ботам, живым **до** действия,
включая вышедших этим действием. Наличие собственного легального хода не важно.
Человек может быть автором действия, не имея мозга в `brains`.
Каждый получатель получает независимую копию `game.getState(id)` и пакета.
Результат `applyAction()` не доставляется: он содержит немаскированные руки.
CLI может передать executor для диагностической записи того же единственного
действия.

## Память и пропуски

`SmartBot.observe(state, id, event)` передаёт пакет в
`CardTracker.observeTransition`; старый интерфейс снимков остаётся доступен.

Повторные/устаревшие номера игнорируются. При разрыве последовательности
забываются все перемещаемые точные факты о чужих руках и предположения.
Известный отбой сохраняется (карты из него не возвращаются), текущий пакет
даёт новые доказанные факты. `unseenDiscardCount` равен разнице между счётчиком
отбоя и известным множеством: потерянные столы не выдумываются.
Reset новой партии сбрасывает номер. Поздно подключённый бот не получает
ретроспективного знания скрытого отбоя.

## Проверка

```sh
npm run build-client
node --test test/publicObservations.test.js
npm test
npm run build-client -- --check
```

Интеграционные тесты сравнивают точные знания с реальными руками движка,
доставляют снимки с маскированием, проверяют легальные решения и восстановление
руки в переходе 4→2. Полные seeded-партии покрывают взятие, перевод и добор
открытого козыря; отдельные тесты — потерю пакета, повтор, reset и исчезновение
последней защиты внутри действия. Для последнего теста очередь подкидывания
явно опустошается подклассом: стандартные правила обычно требуют пасов после
защиты; закрытие, добор и смену раунда выполняет реальный движок.
