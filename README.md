# Переводной дурак — движок игры

Проект развивается по шагам. Сейчас готовы: **игровой движок**, **простые боты**,
**CLI-визуализация**, **WebSocket-сервер с комнатами, лобби, реконнектом и
подменой ботом**, **веб-визуализация** и **отладочный веб-клиент сервера**.
Разделы ниже про "Шаг 1" описывают ядро — движок правил, вокруг которого всё
остальное построено.

## Что внутри

- `src/deck.js` — колода (параметризована: 24 / 36 / 52 карты)
- `src/rules.js` — конфиг всех настраиваемых правил (см. ниже)
- `src/game.js` — движок партии: раздача, ходы, подкидывание, перевод, отбой,
  взятие карт, добор из колоды, определение дурака. Работает через явные
  действия (`attack` / `defend` / `transfer` / `take` / `pass`) — точно так же
  в будущем будет дергаться и реальным игроком через сервер, и ботом.
- `src/bots/simpleBot.js` — бот со базовыми эвристиками (бережёт козыри,
  переводит вместо того чтобы бить козырем, не подкидывает всё подряд).
  Это **не** "сильный" бот — задача этого шага была проверить движок, а не ИИ.
- `src/cli/playVerbose.js` — прогоняет одну партию ботов и печатает полный
  текстовый лог по ходам, чтобы можно было свериться с правилами вручную.
- `src/cli/simulate.js` — прогоняет много партий подряд, чтобы убедиться,
  что движок не падает и не зависает ни при какой комбинации настроек.

## Как запустить (нужен только Node.js, зависимостей нет)

```bash
# Подробный лог одной партии: node src/cli/playVerbose.js <игроков> <колода>
node src/cli/playVerbose.js 2 24
node src/cli/playVerbose.js 4 36
node src/cli/playVerbose.js 6 52

# Массовый прогон для проверки стабильности: node src/cli/simulate.js <партий> <игроков> <колода>
node src/cli/simulate.js 1000 2 24
```

Проверено: **0 ошибок движка на ~3300 автопартий** по всем комбинациям
2–6 игроков × 24/36/52 карты.

## Настраиваемые правила (src/rules.js)

```js
{
  deckSize: 24,          // 24 | 36 | 52
  numPlayers: 2,          // 2..6
  handSize: 6,

  allowPerevod: true,               // "переводной" механизм (сам отключается при 2 игроках)
  perevodOnlyOnFirstCard: true,     // переводить можно только пока ничего ещё не отбито
  perevodRequiresEnoughCards: true, // у принимающего перевод должно хватать карт в руке

  maxTableAttacks: 6,
  attackLimitByDefenderHand: true,
  throwInAfterTake: true,

  throwInPolicy: 'all',  // 'attackerOnly' | 'neighbors' | 'all'
}
```

### Кто может подкидывать карты (`throwInPolicy`)

Настройка выбирается один раз в начале партии (не меняется по ходу игры):

- `'attackerOnly'` — подкидывать может только текущий атакующий.
- `'neighbors'` — подкидывать могут атакующий и игрок, сидящий рядом с
  защищающимся с другой стороны (следующий активный игрок после
  защищающегося по кругу). При 2-3 игроках это совпадает с `'all'`, потому что
  других игроков просто нет.
- `'all'` — подкидывать может любой игрок, кроме самого защищающегося
  (классический вариант, используется по умолчанию).

Порядок подкидывания внутри одного "захода" всегда фиксированный и не
зависит от настройки — она лишь ограничивает, кто из этого порядка
допускается: сначала ходит текущий атакующий, затем — игрок рядом с
защищающимся, затем (только если выбрано `'all'`) остальные игроки по кругу.
Это же правило действует и для повторного подкидывания после того, как
защищающийся забрал карты (`throwInAfterTake`).

Меняется одной строкой при создании игры:
```js
new DurakGame(players, { deckSize: 36, numPlayers: 4, allowPerevod: false });
```

## Известные упрощения / вопросы на уточнение

Это первая версия правил "как я их понимаю" — часть моментов в переводном
дураке имеет несколько распространённых вариаций. Вот что стоит сверить и
при необходимости поправить на следующем шаге:

1. **Кто ходит первым в партии** — сейчас: игрок с младшим козырем на руках.
   Есть вариант "по жребию" или "кто вытянул младшую карту из колоды" — если
   у вас другой вариант, скажите.
2. **Перевод разрешён только первым ходом защиты** (пока ничего не отбито) —
   это самый частый вариант правил, но есть и более вольные версии, где
   переводить можно в любой момент, пока не отбита хотя бы одна карта из
   текущей группы. Сейчас — строгий вариант.
3. **После того как защищающийся забрал карты** — остальные игроки могут
   подкинуть ещё, но только карты тех же рангов, что уже были на столе
   (классическое правило). Можно отключить (`throwInAfterTake: false`).
4. **Ничьи** — если у нескольких игроков одновременно закончились карты и
   колода уже пуста, дурака нет, партия оканчивается вничью. В реальной игре
   так тоже бывает, но частота ничьих в тестах (5-15% на 3+ игроках) стоит
   свериться с вашими ожиданиями — возможно, здесь нужно на строже определять
   порядок, кто первый избавился от карт.
5. **Редкие зависания** (~1 партия из 300-900 на 3+ игроках) — упирается в
   защитный лимит шагов симуляции. Движок не падает, просто конкретная
   партия не доигрывается ботами до конца — нужно будет найти и починить.

### Исправлено после первой версии

- **Добор из колоды не был виден в логе** (сама логика работала верно, не
  печаталось событие) — теперь каждое взятие карт из колоды логируется.
- **Баг с чередованием ролей**: после успешной защиты атакующим в
  следующем раунде должен становиться именно тот, кто только что отбился —
  раньше атакующий всегда пересчитывался как "следующий после
  защищавшегося" независимо от исхода раунда. Теперь: отбился → сам атакует
  дальше; забрал карты → пропускает ход, атакует прежний атакующий.
- **Перевод при игре вдвоём был отключён полностью** — исходно я решил, что
  переводить карту при 2 игроках "некому" (второй игрок и есть атакующий).
  Но это рабочий и распространённый вариант правил: переводящий сам
  становится атакующим, а прежний атакующий обязан отбиваться от
  увеличенной стопки карт того же ранга. Теперь перевод работает и при
  2 игроках (можно по-прежнему отключить через `allowPerevod: false`).
- **Серьёзный баг: подкидывание после взятия карт заново запускало фазу
  защиты.** По правилам, если защищающийся забрал карты со стола, остальные
  игроки могут ещё подкинуть карты тех же рангов (`throwInAfterTake`), но эти
  карты должны просто молча уйти защищающемуся в руку — отбиваться от них не
  нужно. В движке же они снова попадали в `this.table` и запускали
  `defender-to-act`, из-за чего:
  - защищающийся вынужденно "отбивался" второй раз в том же раунде;
  - после разрешения такого квази-раунда карты, которые он "отбил",
    зависали в `this.table` навсегда — не уходили ни в отбой, ни в руку
    (утечка карт, рассинхронизация колоды);
  - из-за этого мусора в `this.table` в следующем раунде переставало
    действовать правило "атакующий не может пасовать первым ходом на
    пустом столе" — стол формально был не пуст.
  Исправлено: подкинутые после взятия карты (`postTakeMode`) теперь сразу
  добавляются в руку защищающегося, без фазы защиты; общий лимит карт за
  раунд (`attackLimitByDefenderHand`) считается отдельным счётчиком
  (`attackCountThisRound`), не зависящим от того, очищался ли стол взятием.
  Проверено на ~4400 автопартиях бот-ботами: 0 нарушений правила "атакующий
  не пасует первым", 0 расхождений в общем числе карт.
