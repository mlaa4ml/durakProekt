# План реализации продвинутого бота (Issue #26)

Этот документ содержит подробный поэтапный план проектирования и реализации продвинутого бота для игры «Переводной дурак» (`durakProekt`). План составлен с учётом предыдущего опыта (issues #24, #25) и требований к предварительному обсуждению перед написанием кода.

---

## 1. Анализ текущей реализации (`src/bots/simpleBot.js` и `src/game.js`)

Текущий простой бот (`simpleBot.js`) принимает решения на основе локальной информации текущей руки и доступных легальных действий (`game.getLegalActions(playerId)`):
- Не анализирует историю карт (что вышло в отбой, что забрали соперники).
- Не строит планы на эндшпиль.
- Не умеет объяснять свои ходы.

Для реализации **продвинутого бота** (`smartBot.js`) нам потребуется:
1. **Модуль отслеживания карт (`CardTracker`)**: ведение истории всех видимых карт (своя рука, стол, бито, забранное оппонентами, козырь под колодой).
2. **Оценка силы руки и фазы игры**:
   - Дебют (много карт в колоде, сохранение сильных некозырных карт, бережное отношение к козырям).
   - Миттельшпиль (активная игра, перевод опасных атак, атака слабыми мастями).
   - Эндшпиль (точный подсчёт оставшихся карт соперников, форсирование победы или минимизация шансов остаться дураком).
3. **Объяснение ходов**: генерация текстового обоснования для каждого решения (например: «Атакую шестёркой червей, так как у меня их больше всего» или «Беру, потому что нет козырей для защиты»).
4. **Интерфейс в локальном клиенте (`visual/index.html` и `docs/index.html`)**:
   - Выбор уровня ботов в настройках лобби («Простой» / «Продвинутый»).
   - Чекбокс включения/выключения логирования объяснений ходов бота.
   - Вывод объяснений в игровой лог (`renderFullLog`).

## 2. Архитектура продвинутого бота (`src/bots/smartBot.js`)

Продвинутый бот будет наследоваться от концепции интерфейса простого бота, но принимать решения по следующей схеме:

```javascript
class SmartBot {
  constructor(playerId, options = {}) {
    this.playerId = playerId;
    this.explain = options.explain || false;
    this.tracker = new CardTracker(playerId);
  }

  chooseAction(state, legalActions) {
    // 1. Обновляем трекер карт на основе текущего состояния
    this.tracker.update(state);

    // 2. Определяем фазу игры (дебют, миттельшпиль, эндшпиль)
    const phase = this.tracker.getPhase(state);

    // 3. Выбираем действие в зависимости от типа хода (атака, защита, перевод, взятие, пас)
    const decision = this.evaluateActions(state, legalActions, phase);

    // 4. Возвращаем выбранное действие и текстовое объяснение (если включено)
    return {
      action: decision.action,
      explanation: this.explain ? decision.explanation : null
    };
  }
}
```

## 3. Этапы реализации (пошаговый план для будущих Issues)

### Этап 1. Создание бенчмарка ботов (`botMatch`)
- **Цель**: Написать CLI-скрипт для автоматического состязания «Простой бот vs Продвинутый бот» (1000 партий, смена мест).
- **Критерий приёмки**: Метрика побед/поражений фиксируется автоматически, создана база для оценки эффективности ИИ.

### Этап 2. Реализация модуля отслеживания карт (`CardTracker`)
- **Цель**: Создать класс, который восстанавливает знания о картах на руках соперников и в колоде.
- **Критерий приёмки**: Корректный подсчет оставшихся карт конкретной масти и ранга.

### Этап 3. Разработка эвристик умного бота (`src/bots/smartBot.js`)
- **Цель**: Реализовать логику выбора действий с учётом фаз игры и просчёта ходов.
- **Критерий приёмки**: Достижение целевой метрики в бенчмарке (умный бот побеждает простого в большинстве партий).

### Этап 4. Добавление генерации объяснений ходов
- **Цель**: Снабзить каждое решение бота человекочитаемым обоснованием.
- **Критерий приёмки**: Возврат структурированного пояснения при активном флаге.

### Этап 5. Интеграция в локальный клиент (`visual/index.html` и `docs/index.html`)
- **Цель**: Добавить UI выбора уровня ботов и отображение их мыслей/объяснений в логах.
- **Критерий приёмки**: Возможность ручного тестирования в браузере.

### Этап 6. Синхронизация и проверка сети
- **Цель**: Перенос изменений в серверную/сетевую логику при успешном прохождении локальных тестов.
- **Критерий приёмки**: Стабильная работа в мультиплеере.
